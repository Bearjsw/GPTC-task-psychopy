# GPTC 행동 선행실험 · 세션 2 (PsychoPy)

`GPTC_행동실험_Ko.pdf` 설계를 PsychoPy로 옮긴 것이다. 기존 `ProjCode_JavaScript.zip`
(PsychoJS, 정보원 4종 + 실제 제품 이미지 322장)은 다른 실험이라 코드를 이어받지
않고 새로 짰다. 새 설계는 화면이 전부 텍스트여서 이미지가 필요 없다.

## 실행

PsychoPy 스탠드얼론을 설치하고 Coder에서 `run_session2.py`를 열어 Run 하면 된다.
터미널에서 돌릴 때는 `pip install psychopy` 뒤에 `python run_session2.py`.

한글이 나오려면 나눔고딕이나 맑은 고딕 중 하나가 깔려 있어야 한다. `config.py`의
`FONT_CANDIDATES`를 앞에서부터 훑어 설치된 첫 폰트를 쓰고, 하나도 없으면 첫
후보 이름을 그대로 넘긴다.

피험자 없이 화면만 보려면 `config.py`에서 `FULLSCREEN = False`로 바꾼다.

## 흐름

```
참가자 정보 입력
(세션 1 자료가 없으면) 제품군 관심도 8문항 -> 삼종 순위 18회
안내 -> 연습 2시행 -> 본 과제 36시행 (중간 휴식 1회)
유사도 15쌍
국면 A 평정 30문항 -> 국면 B 평정 30문항
처리 동기 3문항
```

유사도가 사후 첫 순서라는 점은 바꾸면 안 된다. 뒤 블록이 능력이나 정직성 같은
차원을 먼저 꺼내 놓으면 유사도 판단이 그 차원을 따라가고, 그 값으로 RQ4를
검정하면 순환논증이 된다.

국면 A와 B의 순서는 참가자 ID 끝자리 홀짝으로 갈린다. 절반은 결정 단계를 먼저
답한다.

## 한 시행

```
고정점 (0.5~1.5초 지터)
정보 국면 화면 5초        정보원 라벨 / 제품군 / 후보 3개
  + 평정 1~7             "이 중에 살 만한 게 있어 보입니까?"
고정점
결정 국면 화면 4초        정보원 라벨 / 브랜드 / 가격 / 상세 3줄
  + 산다 · 안 산다
  + 평정 1~7             "얼마나 사고 싶습니까?"
```

자극을 먼저 정해진 시간 동안 보여 주고, 그 화면을 그대로 둔 채 아래에 질문을
띄운다. 발표 자료 15쪽·18쪽 목업과 같은 구성이다.

응답은 좌우 키로 옮기고 Enter로 확정한다. 첫 입력은 방향과 무관하게 가운데(4)에서
시작해서, 어느 쪽 끝에서 출발하느냐가 응답을 밀지 않게 했다. 기존 PsychoJS
코드와 같은 동작이다.

## 제품 8개

구글 시트에서 골랐다. 기준은 세 가지였다. 대분류 4개에서 2개씩, 3~5만원이 그
종류의 자연스러운 가격대일 것, 가상 브랜드로도 후보 비교가 되는 물건일 것.

| 대분류 | 제품군 | 세트 가격 |
|---|---|---|
| ELEC | 블루투스 스피커 | 36,900 / 42,900 / 48,900 |
| ELEC | 저소음 무선 키보드 | 34,000 / 41,000 / 47,000 |
| SELF-CARE | 전동 칫솔 | 33,000 / 39,000 / 46,000 |
| SELF-CARE | 마사지 롤러 | 31,000 / 37,000 / 44,000 |
| STA | 자세교정 방석 | 35,000 / 41,000 / 48,000 |
| STA | 노트북 거치대 | 32,000 / 38,000 / 45,000 |
| CLOTHING | 백팩 | 34,000 / 40,000 / 47,000 |
| CLOTHING | 바람막이 | 36,000 / 43,000 / 49,000 |

FOOD는 전부 뺐다. 브랜드와 원산지가 판단의 전부라 가상 브랜드가 안 통한다
(Ko PDF 15쪽). HOBBY도 뺐다. OTT 구독, 헬스장, 스팀 게임은 물건이 아니어서
가상 브랜드를 붙일 수 없고, 남는 퍼즐 하나로는 카테고리 2개를 못 채운다.

시트 가격이 3~5만원을 벗어난 것은 그 대역의 실제 모델 가격으로 낮췄다. 전동
칫솔 116,055원, 무선 키보드 66,806원이 그런 경우다. 중력 수면 이불은 3~5만원짜리가
부자연스러워서(실제 대역 8~15만원) 같은 SELF-CARE의 마사지 롤러로 바꿨다.

가격은 브랜드가 아니라 세트 단위로 붙였다. 세트 안 세 브랜드가 같은 가격을
쓰기 때문에, 몇 순위 제품이 추천되든 화면의 가격이 같다. 추천 서열과 가격이
엉키는 것을 막으려는 것이다.

## 브랜드명

무작위 알파벳 4~5자에 대소문자를 섞었다. 발표 자료 15쪽의 "Brands are random
from A-Z"를 늘린 것이다. 발음 가능한 조어를 쓰면 음상이 선호를 밀 수 있는데,
그 통로를 막는다.

`config.py`의 `RANDOMIZE_BRAND_NAMES`가 켜져 있으면 참가자마다 이름을 그 자리에서
다시 뽑고, 뽑은 결과를 `brand_names` CSV에 남긴다. `stim/products.csv`에 박힌
이름은 사전 점검이나 눈으로 확인할 때 쓰는 기본값이다. 기본값을 갈아 끼우려면
`python tools_regenerate_brands.py [시드]`.

읽기 부담이 있다는 점은 알아 둘 것. `qXzKt` 같은 이름 셋을 한 화면에서 비교하는
일이라, 사전 점검에서 후보를 못 외우겠다는 반응이 나오면 글자 수를 줄이거나
발음 가능한 조어로 되돌리는 쪽을 검토해야 한다.

## 설계 제약

본 과제 36시행은 아래를 전부 만족한다. `tools_check_design.py`가 이걸 센다.

1. 관심 없다고 고른 제품군 2개를 빼서 6 제품군 x 3 세트 = 18 세트
2. 같은 후보 세트가 딱 2번 등장해서 36시행
3. 두 번 다 같은 제품을 추천하고 정보원만 바뀐다. 후보 배열 순서와 상세 항목까지
   같아서, 두 화면은 라벨 말고 글자가 전부 같다
4. 정보원 6종이 각각 6시행
5. 추천 서열이 정보원당 2/2/2. 참가자가 매긴 1·2·3순위가 각각 두 번씩
6. UT/HE 상세 문구가 정보원당 3/3
7. 같은 정보원이나 같은 제품군이 3연속으로 나오지 않는다
8. 같은 세트의 두 번째 등장까지 최소 6시행 간격

무작위화는 참가자 ID로 시드를 고정한다. 같은 ID로 다시 돌리면 같은 배치가 나온다.

## 세션 1 자료 넣기

추천 제품이 참가자 기준 몇 순위인지 정하려면 세션 1의 삼종 순위가 있어야 한다.
`session1_input/<참가자ID>.csv`를 아래 형식으로 두면 읽는다.

```
excluded,bt_speaker
excluded,windbreaker
rank,keyboard_s1,tUELb,1
rank,keyboard_s1,qqkl,2
rank,keyboard_s1,fFYSu,3
...
```

파일이 없으면 그 자리에서 제품군 관심도와 삼종 순위를 직접 받는다. 세션 1을
아직 안 만든 지금 단계에서 단독으로 돌려 볼 수 있게 한 것이고, 실제 수집에서는
세션 1 자료를 넣는 쪽이 맞다.

브랜드명을 참가자마다 새로 뽑는 설정에서는 세션 1도 같은 이름을 써야 한다.
세션 1을 붙일 때 `brand_names` CSV를 넘기거나, 그때는 `RANDOMIZE_BRAND_NAMES`를
끄고 CSV 기본값으로 고정해야 한다.

## 데이터

`data/` 아래에 블록마다 긴 형식 CSV가 하나씩 생긴다. 한 행이 하나의 응답이고,
행을 쓸 때마다 디스크로 밀어내서 중간에 꺼져도 그때까지는 남는다.

| 파일 | 내용 |
|---|---|
| `*_design_*.csv` | 만들어진 36시행 전체. 과제 시작 전에 쓴다 |
| `*_task_*.csv` | 시행별 응답. 정보 국면 평정, 구매 선택, 구매 의향, 반응시간 |
| `*_similarity_*.csv` | 유사도 15쌍 |
| `*_phase_ratings_*.csv` | 국면 x 정보원 x 문항 60행 |
| `*_processing_*.csv` | 처리 동기 |
| `*_brand_names_*.csv` | 그 참가자가 본 브랜드명 |
| `*_category_interest_*.csv`, `*_set_ranks_*.csv` | 세션 1 자료를 그 자리에서 받았을 때만 |
| `*_meta_*.json` | 참가자 정보, 제외 제품군, 국면 순서, 프레임률, 완료 여부 |

주 분석에 필요한 값은 이렇게 만든다.

- RQ1의 C는 `phase_ratings`에서 `dimension`이 `ability`인 문항과 `benevolence`인
  문항을 각각 평균 낸 뒤, 국면 차이를 한 번 더 뺀다
- RQ2는 `similarity`의 `pair_key`별 값을 6x6 행렬로 펴서 MDS에 넣는다
- 과제 행동은 `task`의 `info_accept`와 `purchase_intent`, `purchase_choice_bin`을
  `source_code` x 국면으로 본다

## 검사 도구

PsychoPy 없이 돌아간다. 자극 CSV를 고친 뒤에는 두 개 다 돌려 보는 것이 좋다.

```
python tools_check_design.py 300     설계 제약을 가상 참가자 300명분으로 센다
python tools_preview.py 7            실제 화면 문구를 터미널에 그린다
```

`tools_check_design.py`는 자극 파일 자체도 본다. 세트 안 세 후보의 축이 서로
다른지, 세트 안 가격이 하나인지, 가격이 3~5만원인지, FOOD가 남아 있지 않은지,
브랜드명이 알파벳 4~5자로 겹치지 않는지를 확인한다.

## 자극 고치기

전부 `stim/` 아래 CSV다. 코드를 건드릴 일이 없다.

- `sources.csv` 정보원 6종. 화면 라벨, 설문에서 부르는 이름, 소개문
- `categories.csv` 제품군 8개. 3개 축, UT 상세 3개, HE 상세 3개
- `products.csv` 브랜드 72개. 제품군, 세트 번호, 이름, 축, 한 줄 특징, 세트 가격
- `questions.csv` 국면별 평정 5문항, 처리 동기 3문항

문항에는 `{src}{이/가}`, `{src}{은/는}` 같은 자리표시자를 쓴다. 정보원 이름의
받침을 보고 조사를 골라 붙인다. ChatGPT처럼 알파벳으로 끝나면 읽는 소리를 기준으로
판정해서 "ChatGPT가", "ChatGPT는"이 된다.

세트를 새로 짤 때 지킬 것은 두 가지다. 세트 안 세 후보의 축이 서로 다를 것,
그리고 세 후보의 매력도가 비슷할 것. 같은 축으로 3개를 만들면 누가 봐도 1등이
정해져서, 2·3등을 추천하는 것이 대놓고 나쁜 걸 권하는 일이 된다.

## 아직 정해야 할 것

- 처리 동기 3문항은 Ko PDF에 이름만 있고 문구가 없어서 임시로 썼다.
  `questions.csv`의 `processing` 행을 팀 문구로 바꿔야 한다
- UT/HE 프라이밍은 발표 자료 19쪽에서 왔고 Ko PDF에는 없다. 세트 단위로 붙여서
  같은 세트의 두 화면이 같게 유지했고 정보원별로 3/3을 맞췄다. 안 쓰기로 하면
  `config.USE_PRIMING`을 끈다
- 자극 72개는 사전 점검(norming)을 아직 안 거쳤다. 제품군 관심도가 한쪽으로
  쏠리지 않는지, 세트 안 3개의 매력도가 비슷한지 확인해야 한다
- 시행 길이를 정보 5초, 결정 4초로 잡아 36시행이 약 10분이 되게 했다. 5~10명에게
  돌려 실측한 뒤 `config.py`에서 조정한다

## 뺀 블록

두 블록을 팀 요청으로 뺐다. 되살릴 일이 생길 수 있어 근거를 남긴다.

**간섭 과제 (덧셈 판단 3분 30초)**

Ko PDF 7쪽은 "두 블록 사이에는 무관한 간섭 과제를 3~5분 넣는다"고 적고 있다.
지금은 두 국면 평정이 바로 이어진다. 정보 단계에 답한 값을 결정 단계에 그대로
옮겨 적기 쉬워지고, 그러면 RQ1의 C값이 0쪽으로 눌린다. 10쪽이 말하는 "그냥
전반적으로 점수가 내려간 경우"와 구별하기 어려워진다는 뜻이다. 사전 점검에서
두 국면의 상관이 지나치게 높게 나오면 이 블록부터 되살리는 것이 맞다.

**조작 점검 (정보원별 설명 회상 6문항 + 검색엔진 광고비 1문항)**

검색엔진 소개문의 "광고비를 낸 제품이 위로 올라오는 일은 없습니다"가 이 실험의
핵심 조작이다(Ko PDF 3쪽). 참가자가 그렇게 받아들였는지 확인할 자료가 지금은
세션 2에 없다. 세션 1의 이해 확인으로 대신하거나, 세션 3에 붙이는 방법이 있다.

되살리려면 `postblocks.py`에 `run_filler` 또는 `run_manipulation_check`를 다시
넣고 `run_session2.py`의 사후 순서에 끼우면 된다. 조작 점검은 `sources.csv`의
`recall_option` 열과 `Source.recall_option` 필드도 함께 되돌려야 한다.
