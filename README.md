# GPTC 행동 선행실험 · 본 과제 (PsychoPy)

사전·사후 설문은 구글 설문으로 받는다. PsychoPy는 **과제만** 돌린다.
설문에 넣을 문항은 `구글설문_문항/` 아래 문서로 빼 두었다.

Rowen이 쓴 `experiment.js`의 구성을 따랐다. 단일 파일 맨 위에 `CFG`로 상수를
모으고, 자극을 정해진 시간 동안 띄운 뒤 지터가 들어간 고정점으로 끊고, 리커트는
원 7개를 좌우 키로 옮겨 Enter로 확정한다. 시행 하나가 CSV 한 행이고 구간별
시각을 열로 남긴다.

## 진행 순서

```
1) 구글 설문 (사전)   참가자 정보 · 정보원 소개문 학습 · 제품군 관심도
       실험자가 응답을 보고 관심도가 가장 낮은 제품군 2개를 적어 둔다
2) PsychoPy 과제      GPTC_task.py     약 12분
3) 구글 설문 (사후)   유사도 15쌍 -> 국면 A -> 간섭 5문항 -> 국면 B -> 처리 동기 -> 조작 점검
```

세 단계를 참가자 ID로 잇는다. 사전 설문에서 부여한 ID를 과제 실행 창에
그대로 입력하고, 사후 설문에서도 같은 ID를 받는다.

## 실행

```
python GPTC_task.py                실제 진행 (전체 화면)
python GPTC_task.py --windowed     창 모드. 화면만 확인할 때
python GPTC_task.py --autopilot    가상 참가자가 자동으로 응답
python GPTC_task.py --record 이름  자동 진행을 녹화해서 이름.mp4 로 저장
```

PsychoPy 스탠드얼론을 쓰면 Coder에서 열고 Run 하면 된다. 터미널이면
`pip install psychopy` 뒤에 위 명령을 쓴다.

실행 창에서 받는 것은 참가자 ID, 연령, 성별, 그리고 **제외할 제품군 2개**다.
제외 제품군은 사전 설문의 관심도 응답을 보고 실험자가 고른다.

## 한 시행

```
고정점 (0.5~1.5초 지터)
정보 국면 5초        [정보원] / 후보 3개 ("eIgx 백팩  -  노트북 전용 칸")
  + 평정 1~7         "이 중에 구매할 만한 게 있어 보입니까?"
고정점
결정 국면 4초        [정보원] / 추천 제품 / 가격 / 상세 3줄
  + 구매한다 · 구매하지 않는다
  + 평정 1~7         "얼마나 구매하고 싶습니까?"
```

자극을 먼저 띄우고, 그 화면을 그대로 둔 채 아래에 질문을 붙인다. 제품군은
따로 한 줄 띄우지 않고 브랜드명 뒤에 붙여서 실제 상품 목록처럼 읽히게 했다.
정보원 라벨은 노란색 큰 글자로 띄운다. 여섯 정보원의 화면 문구가 글자 그대로 같아서
바뀌는 것이 라벨뿐이기 때문이다.

첫 입력은 방향과 무관하게 가운데(4)에서 시작한다. 어느 쪽 끝에서 출발하느냐가
응답을 밀지 않게 하려는 것으로, Rowen 코드와 같은 동작이다.

`Esc`를 누르면 일시 정지 화면이 뜬다. `N`이면 이어서 하고 `Y`면 끝낸다.

## 설계

시행 수는 `CFG`의 숫자에서 나온다.

```
시행 수 = (제품군 수 - 제외 수) x 세트 수 x 반복 수
        = (8 - 2) x 3 x 2 = 36 시행,  정보원 6종에 6시행씩
```

지키는 것은 아래와 같다.

1. 같은 후보 세트가 딱 두 번 나오고, 두 번 다 같은 제품을 추천한다.
   후보 배열 순서와 상세 항목까지 같아서 두 화면은 라벨 말고 글자가 전부 같다
2. 정보원 6종이 각각 6시행을 맡는다
3. 추천 제품이 화면 몇 번째 줄에 있었는지가 정보원마다 고르게 나뉜다
4. 같은 정보원이나 같은 제품군이 3연속으로 나오지 않는다
5. 같은 세트의 두 번째 등장까지 최소 6시행 간격

3번은 원래 "추천이 참가자 기준 몇 순위인가"를 맞추던 자리였다. 사전 설문에서
순위를 받지 않기로 하면서 그 값이 없어졌고, 대신 화면 위치를 맞춘다. 특정
정보원이 늘 맨 윗줄만 추천하는 쏠림을 막는다.

무작위화는 참가자 ID로 시드를 고정한다. 같은 ID로 다시 돌리면 같은 배치가
나온다. 재실행이나 자료 복원 때 필요하다.

## 자극

`stim/` 아래 CSV 세 개뿐이다. 코드를 건드릴 일이 없다. 전부 BOM 붙은 UTF-8이라
엑셀에서 바로 열린다.

| 파일 | 내용 |
|---|---|
| `sources.csv` | 정보원 6종. 화면 라벨, 설문에서 부르는 이름, 소개문 |
| `categories.csv` | 제품군 8개. 코드, 한글명, 대분류, 가격 하한·상한 |
| `details.csv` | 특징 48개. 제품군당 UT 3개 + HE 3개 |

브랜드명은 CSV에 없다. 참가자마다 실행 중에 새로 뽑는다. 알파벳 4~5자에
대소문자를 섞은 무작위 문자열이고, 발음 가능한 조어를 쓰면 음상이 선호를 밀 수
있어서 그 통로를 막은 것이다.

**브랜드와 특징의 짝도 고정하지 않는다.** 매 참가자마다 특징 풀에서 3개를 뽑고,
브랜드명을 3개 만들고, 둘을 섞어 짝짓고, 화면에 놓이는 순서를 또 섞고, 가격도
범위 안에서 뽑는다. 뽑힌 결과는 데이터 CSV에 전부 남는다.

가격은 브랜드가 아니라 세트 단위로 붙는다. 세 후보가 같은 가격을 쓰기 때문에
어느 후보가 추천되든 결정 국면의 가격이 같고, 추천과 가격이 엉키지 않는다.

### 제품군 8개

대분류 4개에서 2개씩 골랐다. 3~5만원이 그 종류의 자연스러운 가격대이고,
가상 브랜드로도 후보 비교가 되는 물건만 넣었다.

| 대분류 | 제품군 | 가격 범위 |
|---|---|---|
| ELEC | 블루투스 스피커 | 33,000 ~ 49,000 |
| ELEC | 저소음 무선 키보드 | 32,000 ~ 48,000 |
| SELF-CARE | 전동 칫솔 | 31,000 ~ 47,000 |
| SELF-CARE | 마사지 롤러 | 30,000 ~ 44,000 |
| STA | 자세교정 방석 | 33,000 ~ 48,000 |
| STA | 노트북 거치대 | 30,000 ~ 45,000 |
| CLOTHING | 백팩 | 33,000 ~ 49,000 |
| CLOTHING | 바람막이 | 34,000 ~ 50,000 |

FOOD는 전부 뺐다. 브랜드와 원산지가 판단의 전부라 가상 브랜드가 안 통한다.
HOBBY도 뺐다. OTT 구독, 헬스장, 스팀 게임은 물건이 아니어서 가상 브랜드를
붙일 수 없고, 남는 퍼즐 하나로는 카테고리 2개를 못 채운다.

세트를 새로 짤 때 지킬 것은 세 후보의 매력도가 비슷해야 한다는 점이다. 한쪽이
확실히 나으면 2·3등을 추천하는 것이 대놓고 나쁜 걸 권하는 일이 된다.

## 데이터

`data/` 아래에 참가자마다 CSV 하나와 meta JSON 하나가 생긴다. 한 행이 한 시행이고
BOM 붙은 UTF-8이다.

주요 열은 아래와 같다.

| 열 | 내용 |
|---|---|
| `TrialNumber`, `block` | 시행 번호, 연습인지 본 과제인지 |
| `source_code`, `source_label` | 그 시행의 정보원 |
| `category_kr`, `set_key`, `price` | 제품군, 세트, 가격 |
| `Candidates`, `Details` | 화면에 놓인 순서대로의 브랜드명과 특징 |
| `rec_position`, `rec_brand`, `rec_detail`, `rec_detail_type` | 추천 제품과 그 특징 |
| `ExtraLines` | 결정 국면에서 특징 아래 붙은 줄 |
| `InfoAccept`, `InfoAccept_RT` | 정보 국면 평정 1~7과 반응시간 |
| `PurchaseChoice`, `PurchaseChoice_bin`, `_RT` | 구매한다·구매하지 않는다 |
| `PurchaseIntent`, `_RT` | 구매 의향 1~7 |
| `fix1.*`, `info.*`, `fix2.*`, `decision.*` | 구간별 시작·종료 시각 |

과제 행동은 `source_code`별로 `InfoAccept`(정보 국면)와 `PurchaseIntent`·
`PurchaseChoice_bin`(결정 국면)을 비교해서 본다. 정보 국면에서는 대등한데 결정
국면에서 밀리는 정보원이 있는지가 보고 싶은 것이다.

## 알아 둘 것

**한국어 윈도우에서 PsychoPy가 import 단계에서 죽는다.** `psychopy.gui`가 부르는
i18next가 한국어 번역 JSON을 열 때 인코딩을 지정하지 않아 시스템 기본값(cp949)으로
읽다가 UnicodeDecodeError를 낸다. `GPTC_task.py`가 UTF-8 모드로 스스로 다시 띄워서
피해 간다. 손댈 것은 없다.

**Python 3.12에서 글자가 하나도 안 그려진다.** PsychoPy가 윈도우에서 고정해 둔
pyglet 1.4.11이 3.12에서 깨진다. `TextStim` 대신 `TextBox2`를 써서 피했다.
PsychoPy 스탠드얼론(Python 3.10)에서는 둘 다 되지만 코드는 그대로 쓰면 된다.

**엑셀에서 한글이 깨지면** CSV에 BOM이 빠진 것이다. 이 폴더의 CSV는 전부 BOM을
붙여 두었고, 과제가 쓰는 데이터 CSV도 마찬가지다.

## 남은 것

- 처리 동기 문항은 원 설계 문서에 이름만 있고 문구가 없어서 임시로 썼다.
  구글 설문에 넣기 전에 팀 문구로 바꿔야 한다
- 자극 48개는 사전 점검(norming)을 아직 안 거쳤다. 제품군 관심도가 한쪽으로
  쏠리지 않는지, 세트 안 세 후보의 매력도가 비슷한지 확인해야 한다
- 시행 길이를 정보 5초, 결정 4초로 잡아 36시행이 약 12분이 되게 했다.
  5~10명에게 돌려 실측한 뒤 `CFG`에서 조정한다
- 간섭 과제는 PsychoPy가 아니라 구글 설문에 있다. 두 국면 평정 블록 **사이**가
  제자리다. 과제 끝에 두면 두 블록이 붙어서 진행되어 원래 목적을 못 한다
